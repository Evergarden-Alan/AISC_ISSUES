## 1. 项目概述

### 1.1 一句话定位

AISC_ISSUES 反馈站是软件 **AISC_ISSUES**（单产品）的官方反馈站，收集**问题反馈**与**需求反馈**两类内容：**GitHub Issues 的平民化前端**——不懂编程的中国大陆用户用中文填一张表、传几张截图，就能把问题或想要的功能变成一条开发者看得到、能回复、用户自己也能回访查看的反馈（存储为私有 GitHub 反馈仓库中的 `feedback/{id}.md`）。

### 1.2 目标用户画像

- **身份**：AISC_ISSUES 软件的使用者，中国大陆居民，不懂编程，绝大多数不知道 GitHub 是什么。
- **设备与环境**：以手机为主（Android 居多）；反馈站链接**常在微信/QQ 群或私聊中打开，默认运行在微信/QQ 内置浏览器**，而非独立浏览器；网络环境下 GitHub 及部分境外资源不可达，因此所有图片、附件一律经本站 `/api/asset` 代理访问，页面不加载任何墙外资源。
- **能力水平**：会截图、会在微信里发图、会复制粘贴；不理解「仓库」「Issue」「token」「frontmatter」；在长表单、英文界面、验证码、注册登录环节极易流失。因此：v1 无任何登录，表单默认只有少量必填项，全部文案口语化。
- **诉求与顾虑**：把「软件出问题了」说清楚；之后能看到开发者的回复；担心泄露隐私、担心填了没人理。

### 1.3 产品范围（里程碑）

| 里程碑 | 范围 |
| --- | --- |
| M1 | 只读回信区（双 Tab：「问题」与「功能建议」）+ 两条路径的基本提交（无附件、无 token 详情页） |
| M2 | 截图 + 日志附件（仅问题路径）+ 编号查询 + 专属详情页 `/issue/{id}?t={token}` |
| M3 | 列表筛选搜索（状态/类型筛选（含 问题/功能 维度）+ 关键词搜索）+ 轻统计 + 受保护管理页（可选） |

v1 非目标（明确不做）：账号体系、邮件通知、管理后台、多语言、统计模块、国内验证码/短信、多产品切换 UI、功能需求投票。

## 2. 完整用户旅程

以下六步为一条完整主线。每步给出【界面要素】与【完整文案】；文案为定稿，开发时直接使用。

### 步骤 1：发现站点（链接打开后 3 秒内看懂这是干什么的）

- 场景：用户在微信/QQ 里点开开发者分享的链接，落在首页 Hero 区。
- 判定标准：不滚动页面，首屏内可见——主标题、副标题、主 CTA「我要提反馈」、SLA 文案「我们通常在 3 个工作日内回复」。
- 首屏文案见 3.1 节 Hero 定稿。

### 步骤 2：进入表单（3 秒理解要填什么）

- 界面要素：表单页标题、**两张路径大卡片二选一（第 4.0 节：「我遇到了问题」/「我想要新功能」）**、隐私提示条、选中问题路径后默认展开的基本反馈字段（第 4.1 节 5 项）、折叠的详细反馈区（第 4.2 节）、底部提交按钮、环境信息自动采集告知（小字）。
- 文案：
  - 页面标题：**提交反馈**
  - 顶部隐私提示条（浅警示底色 + 盾形图标）：**提交前请注意：请勿填写密码、手机号等敏感信息。**
  - 主按钮（吸底或表单底部，固定）：**提交反馈**
- 选完路径后第一眼可见的必填项（问题路径）只有 3 个（问题类型 / 一句话概括 / 详细描述）+ 1 个口语化影响程度选择；功能路径必填仅 2 项（一句话概括想要的功能 / 详细描述），详见第 4 节。

### 步骤 3：填写与上传

- 界面要素：路径二选一大卡片（第一步）、大卡片单选（问题类型，仅问题路径）、三档口语化选择（影响程度，仅问题路径）、文本输入、截图添加按钮、可展开的详细反馈折叠区（仅问题路径）。
- 交互要点：
  - 截图点「添加截图」从相册选择或拍照；选中的图显示缩略图 + 删除按钮；客户端自动压缩并去除位置信息（EXIF），用户无感知。
  - 日志附件在展开详细折叠区后上传，逐个显示上传进度条。
  - 全程草稿自动保存（localStorage），页面顶部或字段区淡入提示：**草稿已自动保存**（2 秒后淡出）。

### 步骤 4：提交

- 界面要素与文案：
  - 点击「提交反馈」后按钮禁用并显示：**正在提交…请不要关闭页面**
  - 服务端冲突（编号撞车 409/422）自动换随机串重试，最多 3 次，指数退避，**用户无感知**，不展示中间态。
  - 三次重试后仍失败 → 进入失败态（原页面，表单内容全部保留）：**提交暂时没有成功，可能是网络问题。您填写的内容都保留着，请稍后点「重新提交」再试一次。**（附「重新提交」按钮）
  - 触发限频时的提示（覆盖在表单上方的提示条）：
    - 60 秒冷却内：**您操作有点快，请 1 分钟后再提交。**
    - 当日超 5 次/小时：**您今天提交的反馈有点多，请 1 小时后再来。**
  - 提交成功后清除本地草稿。

### 步骤 5：提交成功（拿到编号与专属链接）

- 界面要素与文案见第 6.1 节成功页规格。核心：大号等宽字体展示反馈编号（如 `20260921-143025-a1b2c3`）+「复制编号」按钮 + 专属详情页链接 `/issue/{id}?t={token}` +「复制链接」按钮 + 收藏/截图保存提示。

### 步骤 6：回访与看到回信

- 两条回访路径：
  1. 打开收藏的专属链接 `/issue/{id}?t={token}`（提交成功时已被提示收藏或截图保存）；
  2. 回到首页，在「按编号查询」输入编号进入详情页。
- 详情页要素：当前状态中文徽章（如「已回复」）、原反馈全文（含截图/附件）、开发者回复时间线（多轮按时间正序）、称呼展示（未填则不显示该行）。
- 无回复时的空态文案：**开发者还没有回复。我们通常在 3 个工作日内回复，请过几天再来看看。**

## 3. 首页信息架构

首页自上而下共四个区块：Hero 引导区 → 按编号查询 → 开发者回信区 → 页脚。单列布局（见第 7 节）。

### 3.1 Hero 引导区（定稿文案）

| 要素 | 文案 |
| --- | --- |
| 主标题（H1） | **遇到问题，或想要新功能？** |
| 副标题 | **1 分钟提交，开发者会回复。** |
| SLA（副标题下小字） | **我们通常在 3 个工作日内回复。** |
| 主 CTA 按钮 | **我要提反馈**（链接到表单页） |
| 次 CTA（次级按钮或文字链） | **我有编号，查进度**（锚点到本页「按编号查询」区） |

### 3.2 按编号查询区

- 上线范围：**M2+**（基线将编号查询列于 M2；M1 首页不渲染本区块，Hero 次 CTA「我有编号，查进度」同步隐藏）。
- 区块标题：**按编号查询**
- 输入框占位符：**请输入反馈编号，如 20260921-143025-a1b2c3**
- 按钮：**查询**
- 结果行为：
  - 编号存在且未隐藏 → 进入该反馈详情页。
  - 编号不存在或格式错误 → 行内错误：**没找到这个编号。请检查是否输错（编号形如 20260921-143025-a1b2c3）。**
  - 编号对应 `status=hidden` → 详情页位置显示：**该反馈已被隐藏，无法查看。**

### 3.3 开发者回信区（首页下方，双 Tab）

- 区块标题：**开发者最新回复**，其下分两个 Tab：**「问题」**（问题反馈路径条目）与**「功能建议」**（需求反馈路径条目），默认停在「问题」Tab。
- 展示规则：两个 Tab 各自只展示「## 开发者回复」分区**已有实际内容**（非"（暂无）"占位）的对应路径条目；按 `updated_at` 倒序，各 Tab 最多 **10 条**。
- 条目结构（每条为一个可点击卡片，点击进入该反馈详情页）：
  1. 反馈标题（`title`，原文）
  2. 标签组：类型中文标签 + 状态中文标签（状态用双映射：问题 Tab 用问题列文案，功能 Tab 用功能列文案；样式见 3.4）
  3. 回复摘要：取最新一轮开发者回复正文，去除 Markdown 格式后截断至约 100 字，超出以「…」结尾
  4. 更新时间：`updated_at`，格式 `YYYY-MM-DD HH:mm`（如 2026-09-18 14:30）
- 「查看全部」入口：按钮 **查看全部回复** → M3 的列表页（状态/类型筛选（含 问题/功能 维度）+ 关键词搜索）。M1/M2 阶段不渲染该入口（列表页属 M3 范围）。
- 空态文案（两 Tab 通用）：**我们通常在 3 个工作日内回复。**

### 3.4 中文标签映射与样式说明

frontmatter 枚举值一律英文小写入库，前端按下表映射为中文展示（status 按路径双映射，同一枚举两套文案）：

| 枚举 | 字段 | 中文文案（问题路径 / 功能路径） | 标签样式（回信区/详情页徽章通用） |
| --- | --- | --- | --- |
| `bug` | type | 程序出错或闪退 | 中性灰底圆角胶囊 |
| `feature` | type | 功能建议 | 中性灰底圆角胶囊 |
| `ux` | type | 用着别扭不顺手 | 中性灰底圆角胶囊 |
| `question` | type | 不会用有疑问 | 中性灰底圆角胶囊 |
| `other` | type | 其他 | 中性灰底圆角胶囊 |
| `submitted` | status | 已收到（两路径同） | 灰底 |
| `in-progress` | status | 处理中 / 开发中 | 蓝底 |
| `replied` | status | 已回复（两路径同） | 绿底（强调色） |
| `resolved` | status | 已解决 / 已上线 | 深绿实心 |
| `wontfix` | status | 暂不处理 / 暂不计划 | 橙底 |
| `duplicate` | status | 重复（两路径同） | 灰蓝底 |
| `hidden` | status | 已隐藏（两路径同） | 列表不展示；直接访问详情页时整页提示「该反馈已被隐藏，无法查看。」 |
| `blocker` | severity | 完全没法用了（仅问题路径） | 红底徽章（仅详情页展示） |
| `normal` | severity | 能用但别扭（仅问题路径；功能路径不采集、服务端固定写 normal，不展示） | 橙底徽章（仅详情页展示） |
| `low` | severity | 小问题（仅问题路径） | 灰底徽章（仅详情页展示） |
| `basic` | tier | 基本反馈 | 不对用户展示（内部字段） |
| `detailed` | tier | 详细反馈 | 不对用户展示（内部字段；功能路径固定 basic） |

标签通用规格：圆角胶囊（radius-full），字号 12px，字重 500，文字与底色对比度 ≥4.5:1；不使用纯色差传达含义，标签本身即文字。

### 3.5 页脚（定稿文案）

- 行 1：**AISC_ISSUES 反馈站 · 专门收集 AISC_ISSUES 软件的使用反馈**
- 行 2：**反馈内容将以文本形式存入 GitHub 仓库，供开发者查看和处理。我们通常在 3 个工作日内回复。**
- 行 3：**© {当前年份} AISC_ISSUES**

## 4. 表单逐字段规格表

表单页：`/submit`（与 03 文档目录 `src/app/submit/page.tsx` 对应）。顶部隐私提示条与提交按钮见第 2 节步骤 2/4。字段按页面出现顺序排列。表单第一步为双路径二选一（4.0 节），其后字段按所选路径展示（问题路径见 4.1/4.2，功能路径见 4.3）。

### 4.0 第一步：双路径二选一大卡片（定稿）

进入表单先看到两张并排大卡片（竖排网格，单选，卡片含图标 + 主文案 + 一句副文案），选中其一后展示对应路径字段：

| 路径 | 卡片主文案 | 卡片副文案 | 后续字段 |
| --- | --- | --- | --- |
| 问题反馈路径 | **我遇到了问题** | 软件出了故障、用着别扭或有疑问 | 第 4.1 节 + 第 4.2 节（type 最终 ∈ {bug, ux, question, other}） |
| 需求反馈路径 | **我想要新功能** | 希望软件增加新能力 | 第 4.3 节（type 固定 `feature`，无需再选类型） |

- frontmatter 的 `type` 仍为五值枚举 {bug, feature, ux, question, other}，UI 组织方式不影响存储枚举；`category`（issue/feature）为读取时派生值，不写入 frontmatter。
- 草稿保存含所选路径，刷新/恢复后回到同一路径（见 5.4 节）。

### 4.0.1 同一会话内切换路径不丢内容

- 第一步两张大卡片（我遇到了问题 / 我想要新功能）允许反复切换，切换不清空任何已填内容；切换时轻提示「已切换到 XX反馈，已填内容已保留」。
- 共用字段跨路径保留：title、description、nickname、已上传截图（含 _pending 引用与缩略预览；两条路径共用同一组截图槽位，均 ≤3 张）。
- 路径专属字段按路径分桶暂存，切走再切回时原样恢复：issue 桶 = type、severity、steps、expected、actual、attachments（详细档附件仅问题路径）；feature 桶 = scenario、workaround。
- localStorage 键 `aisc:draft` 为单一键，值为按路径分桶的 JSON：
  { "version": 1, "path": "issue" | "feature", "shared": { "title": "", "description": "", "nickname": "", "screenshots": [] }, "issue": { "type": null, "severity": "normal", "steps": "", "expected": "", "actual": "", "attachments": [] }, "feature": { "scenario": "", "workaround": "" }, "savedAt": "ISO 8601 (+08:00)" }
  （path 记录最后所选路径，刷新/恢复回到该路径。）

### 4.1 问题反馈路径 · 基本反馈字段（默认展示）

| # | 字段名 | 控件类型 | 必填 | 限制 | 标签文案（口语化） | 占位符示例 | 错误提示文案 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `type` 问题类型 | 大卡片单选（竖排网格，4 选 1，卡片含图标 + 主文案 + 一句副文案） | 必填 | 枚举：`bug`/`ux`/`question`/`other`（问题路径不出现 `feature`） | 这个问题属于哪一类？ | 不适用。卡片文案见下方补充 | 请先选择问题类型 |
| 2 | `severity` 影响程度 | 三档口语化单选（三张小卡或分段控件，默认不预选） | 必填（仅问题路径采集；已定稿：必填） | 枚举：`blocker`/`normal`/`low` | 这对您使用的影响有多大？ | 不适用。卡片文案：完全没法用了 / 能用但别扭 / 小问题 | 请选择影响程度 |
| 3 | `title` 一句话概括 | 单行文本输入 | 必填 | ≤50 字（按字符计），右下角实时字数「n/50」 | 用一句话概括问题 | 例：导出文件时软件卡住不动了 | 请填写一句话概括；不能超过 50 字 |
| 4 | `description` 详细描述 | 多行文本域（自适应高度，初始 5 行） | 必填 | ≤2000 字（按字符计），右下角实时字数「n/2000」 | 详细说说发生了什么 | 什么时候开始的？您当时在做什么？屏幕上出现了什么提示？ | 请填写详细描述；不能超过 2000 字 |
| 5 | `screenshots` 现场截图 | 文件上传（图片多选；按钮「添加截图」，选中后显示缩略图 + 单张删除） | 选填 | ≤3 张；仅 `.jpg`/`.png`/`.webp`；选择后客户端压缩至 ≤4MB/张并经 canvas 重绘剥除 EXIF（含位置信息），用户无感知 | 现场截图（可不传，最多 3 张） | 按钮文案：添加截图（支持拍照） | 仅支持 JPG / PNG / WebP 图片，最多 3 张 |

## 5. 两档反馈交互

> 术语约定：本文档统一使用「问题反馈」（问题反馈路径，type ∈ {bug, ux, question, other}）与「需求反馈」（需求反馈路径，type 固定 `feature`）指代两条路径；「基本反馈」（`tier=basic`）与「详细反馈」（`tier=detailed`）指代问题路径内的两档；「基本反馈字段」= 第 4.1 节默认展示字段，「详细反馈折叠区」= 第 4.2 节折叠区（标题「上传软件日志等辅助材料（可选）」，仅问题路径提供）。需求反馈路径固定 `tier=basic`，无档位之分。

### 5.1 默认基本反馈

打开表单先做路径二选一（第 4.0 节）；选中问题路径后即处于基本反馈档：可见字段 = 第 4.1 节 1–5 项 + 提交按钮。用户不看折叠区也能完整提交一条基本反馈（`tier=basic`）。选中功能路径则展示第 4.3 节字段（`tier` 固定 `basic`）。

### 5.2 详细反馈折叠区展开逻辑

- 位置：基本反馈字段之后、提交按钮之前。
- 标题固定为 **上传软件日志等辅助材料（可选）**，右侧展开/收起箭头，动画 ≤200ms。
- 展开后显示字段 6（日志附件）与字段 7（怎么称呼您）。
- 收起不丢内容：若折叠区内已有上传的附件或已填称呼，收起后在标题右侧显示「已添加」小徽标，展开后内容原样保留。
- 提交时档位判定（`tier`）：问题反馈路径——表单提交内容包含日志附件 → 该条反馈 `tier=detailed`；否则 → `tier=basic`。依据基线定义「详细反馈 = 用户上传软件日志等辅助材料」，称呼不参与档位判定。需求反馈路径固定 `tier=basic`（不提供日志附件上传）。
- 运维附注：用户上传附件后放弃提交，临时文件将留在暂存目录（`feedback/assets/_pending/{uuid}`）；v1 不做自动清理。

### 5.3 环境信息自动采集的用户告知文案

表单描述区底部固定小字（与提交按钮之间，不折叠、常显）：

> **提交时会自动附上您的设备信息（操作系统、浏览器、所在页面、提交时间），帮助我们更快定位问题，无需您填写。**

### 5.4 草稿与降级（三层）

1. **草稿层**：填写过程实时保存到浏览器 localStorage，触发保存时淡入提示「草稿已自动保存」；刷新/误关后重开表单自动恢复；提交成功后清除。
2. **重试层**：提交失败自动换随机串重试 ≤3 次（用户无感知），见第 2 节步骤 4。
3. **保留层**：自动重试全部失败后，表单停留在失败态且**所有已填内容、已上传附件均保留**，用户可稍后点「重新提交」。

## 6. 提交成功页与详情页

### 6.1 提交成功页（路径 `/submit/success`，需满足以下全部要素；M1 阶段无专属详情页，成功页仅展示编号、「复制编号」与 SLA，不渲染专属链接区）

- 标题（H1）：**提交成功，谢谢您！**
- **编号区**：
  - 标签：您的反馈编号
  - 编号：大号等宽字体展示，如 `20260921-143025-a1b2c3`
  - 按钮：**复制编号**（点击后文案短暂变为「已复制」；剪贴板 API 不可用时展示可长按选择的纯文本编号 + 提示「长按编号可复制」，见第 7.4 节）
- **专属链接区**：
  - 标签：查看进度的专属链接
  - 链接：`/issue/{id}?t={token}` 完整地址 + 按钮 **复制链接**
  - 提示文案：**这个链接就是您反馈的凭证，请收藏（点右上角「…」菜单）或截图保存。之后打开它，就能看到开发者的回复。**
  - 回退提示：**如果链接丢了，也可以回首页，在「按编号查询」里输入编号找回。**
- 主按钮：**查看我的反馈**（跳转该专属链接）；次按钮：**返回首页**。
- 页尾 SLA：**我们通常在 3 个工作日内回复。**

### 6.2 专属详情页 `/issue/{id}?t={token}`

页面自上而下：

1. **头部**：状态中文徽章（如「已回复」，按路径用双映射文案）+ 类型中文标签 + 影响程度徽章（仅问题路径展示）+ 反馈编号（小字）+ 提交时间（`created_at`，`YYYY-MM-DD HH:mm`）。
2. **原反馈区**：按正文分区模板渲染（与 02 文档 §3 两套模板一致）——
   - 问题反馈路径（8 分区）：问题描述 / 复现步骤（仅 `type=bug` 时出现）/ 期望结果 / 实际结果 / 环境信息（自动采集内容，折叠展示，默认收起，标题「设备与环境信息」）/ 截图 / 附件 / 开发者回复；
   - 需求反馈路径（7 分区）：想要的功能 / 想解决的问题 / 使用场景 / 现状的替代办法 / 环境信息（仅浏览器 UA 与提交时间，折叠展示，默认收起）/ 截图 / 开发者回复。
   - 截图：缩略图网格，点击放大查看（灯箱，支持左右切换、双指缩放）。
   - 附件：文件名 + 大小 + 「下载」链接。图片与附件一律经本站 `/api/asset` 代理加载（路径白名单限 `feedback/assets/` 内），不直连 GitHub。
3. **称呼**：`nickname` 原文展示（未填则整行不显示）。v0.1.0 起不采集任何联系方式（邮箱/微信/QQ 字段已移除），无打码逻辑（`src/lib/mask.ts` 不创建）。
4. **开发者回复时间线**：每轮回复一条，头部为「开发者 · YYYY-MM-DD HH:mm」（来自正文中 `### YYYY-MM-DD HH:mm 开发者` 标记），正文按时间正序排列；最新一轮在最下方。
5. **空回信态**（「## 开发者回复」区为空）：**开发者还没有回复。我们通常在 3 个工作日内回复，请过几天再来看看。**
6. **隐藏态**（`status=hidden`）：整页仅显示 **该反馈已被隐藏，无法查看。**

> ⚠️ 待确认 ②：基线同时规定「专属详情页链接（token）」「首页按编号查询（无 token）」与「回信区条目可点击查看」三件事，但未明确详情页的访问控制边界——若详情页强制校验 token，则按编号查询与回信区条目将无法进入详情页，三者互相矛盾。本文档采用的方案：**详情页本身公开可访问（编号中 6 位随机串已提供不可枚举性），`t` 参数作为提交者凭证随专属链接携带但不作强制拦截；回信区条目与按编号查询均进入同一公开详情视图；称呼（nickname）在任何视图下原文展示。**
>
> ✅ **已拍板（2026-09-22）：按本文档方案执行（详情页公开可访问、token 不强制拦截），即为定稿。**

## 7. 移动端与无障碍基线

### 7.1 布局与尺寸

- 全站单列布局，主内容最大宽度 640px 居中；桌面端同样单列居中。
- 所有输入框字号 ≥16px（防 iOS Safari 聚焦自动缩放）。
- 所有可点击目标（按钮、卡片、单选项、删除图标、复制按钮）≥44×44px。
- 底部安全区：页面与吸底按钮 `padding-bottom: env(safe-area-inset-bottom)`，内容不被手势条遮挡。
- 软键盘弹出时当前聚焦控件自动滚动至可视区；键盘收起后页面恢复正常滚动位置。

### 7.2 表单无障碍

- 每个输入项 label 显式关联（`<label for>` / `id`）；大卡片单选用 `input[type=radio]`（视觉隐藏原生控件）+ label 包裹，键盘可操作。
- 错误呈现：文字 + 红色警示图标，置于字段下方，通过 `aria-describedby` 关联；提交失败时滚动到第一个错误字段并聚焦；**不得只靠颜色传达错误**。
- 文字对比度：正文、标签、占位符提示、状态徽章文字与各自底色对比度 ≥4.5:1。
- 动效仅用于折叠展开与淡入淡出，≤200ms，尊重 `prefers-reduced-motion`。
- 页面 `<html lang="zh-CN">`；viewport 允许系统缩放（不设 `user-scalable=no`、不设 `maximum-scale`）。

### 7.3 触控细节

- 截图缩略图、附件删除、标签卡片均提供足够间距（≥8px），防误触。
- 一键复制按钮同时提供结果反馈（「已复制」文字变化），不只靠短暂高亮。

### 7.4 微信/QQ 内置浏览器注意事项

- **file input 差异**：Android 微信对 `multiple` 多选支持不稳定——截图上传按「一次添加、可多次点击『添加截图』累计至 3 张」设计（`multiple` 可保留为渐进增强）；不强制 `capture` 仅拍照属性，保留相册/拍照系统选择。
- **剪贴板差异**：`navigator.clipboard` 在部分内置浏览器不可用或要求特定手势——「复制编号/链接」必须实现降级：选中纯文本并提示**长按编号可复制**。
- 不弹「请用其他浏览器打开」类引导（流失极高）；不依赖 webkit 私有 API；图片懒加载避免内置浏览器内存回收导致白屏。
- localStorage 在内置浏览器隐私模式可能被禁用，读写需 try/catch，草稿功能静默降级（无提示失败，仅不再显示「草稿已自动保存」）。

### 表单

- [ ] 打开表单第一步为两张路径大卡片二选一（「我遇到了问题」/「我想要新功能」，文案见 4.0 节）；选问题路径后默认为基本反馈：可见字段为类型（4 卡：程序出错或闪退/用着别扭不顺手/不会用有疑问/其他）/影响程度/一句话概括/详细描述/截图 + 提交按钮；详细区默认折叠，标题为「上传软件日志等辅助材料（可选）」。
- [ ] 选功能路径后展示 4.3 节字段：无类型选择（固定 `feature`）、无影响程度项、无日志附件折叠区；截图/参考图与称呼可用。
- [ ] 类型未选提交（问题路径）→ 「请先选择问题类型」；影响程度未选提交（问题路径）→ 「请选择影响程度」。
- [ ] `title` >50 字、`description` >2000 字均被拦截并显示对应错误文案；字数计数器实时可见（功能路径的概括/描述同限）。
- [ ] 截图（M2+，已定稿属 M2；两条路径均可传）：第 4 张被拒；非 jpg/png/webp 被拒；大图经客户端压缩至 ≤4MB/张且 EXIF 被剥离（用带 GPS 的照片验证）；可单张删除。
- [ ] 附件（M2+，仅问题路径）：非 .log/.txt/.json/.zip 被拒；>3MB 被拒；第 4 个被拒；三条错误文案逐条验证；单个附件上传失败可重试或删除，不阻塞其他附件；功能路径表单无附件入口，请求体带附件引用被服务端 400。
- [ ] 表单无任何联系方式字段；「怎么称呼您」选填、≤20 字、超长报「称呼不能超过 20 字」。
- [ ] 表单顶部隐私提示「提交前请注意：请勿填写密码、手机号等敏感信息。」可见。
- [ ] 环境信息告知文案「提交时会自动附上您的设备信息…」可见，且环境信息不出现在任何表单项中。
- [ ] 蜜罐字段：页面上不可见、Tab 键无法聚焦；脚本填入后服务端不写入仓库并返回伪成功响应（反馈仓库无新文件），不暴露判定结果。
- [ ] 草稿：填写后刷新页面内容恢复并出现「草稿已自动保存」提示；提交成功后草稿清除；localStorage 禁用时静默降级。
- [ ] 问题↔功能切换后回到原路径：共用字段（概括/详细描述/称呼/截图）与该路径专属字段均在；刷新后回到最后所选路径

### 提交链路与降级

- [ ] 重复快速点击「提交反馈」只产生一条反馈（幂等键生效）。
- [ ] 断网/服务端 5xx：自动重试后进入失败态，表单内容与附件全部保留，可点「重新提交」成功。
- [ ] 限频：60 秒内二次提交显示「您操作有点快，请 1 分钟后再提交。」；超出 5 次/小时显示「您今天提交的反馈有点多，请 1 小时后再来。」
- [ ] 档位判定：问题路径无日志附件提交 → `tier=basic`；含日志附件 → `tier=detailed`；功能路径任何提交 → `tier=basic`、`severity="normal"`（检查 `feedback/{id}.md` frontmatter）。
- [ ] 落库结构：反馈写入 `feedback/{id}.md`，附件归位 `feedback/assets/{id}/`，`id` 格式为 `YYYYMMDD-HHmmss-{6 位随机小写字母数字串}`。

### 成功页与详情页（M2+）

- [ ] 成功页展示编号（等宽大字）+「复制编号」+ 专属链接 `/issue/{id}?t={token}` +「复制链接」+ 收藏/截图保存提示文案。
- [ ] 「复制编号」「复制链接」在 iOS Safari 与微信内置浏览器可用，或正确降级为「长按编号可复制」。
- [ ] 详情页依次展示头部徽章/标签/编号/时间、原反馈分区、截图灯箱、附件下载、称呼（如有）、回复时间线。
- [ ] 任何页面不出现联系方式字段；frontmatter 含 `nickname` 时按原文展示，无则不显示该行。
- [ ] 无回复时详情页空态显示「开发者还没有回复。我们通常在 3 个工作日内回复，请过几天再来看看。」
- [ ] `hidden` 状态详情页整页仅显示「该反馈已被隐藏，无法查看。」

### 回信闭环

- [ ] 开发者在 `## 开发者回复` 下按 `### YYYY-MM-DD HH:mm 开发者` 格式追加回复并更新 `status`/`updated_at` 后，≤300 秒内首页回信区出现该条目（问题条目进「问题」Tab、功能条目进「功能建议」Tab），状态徽章与中文双映射一致（依 3.4 节映射表逐项核对）。

### 移动端与无障碍

- [ ] 375px 宽度下全站无横向滚动，单列布局，内容最大宽度 640px。
- [ ] 输入框 computed font-size ≥16px；触摸目标 ≥44×44px（用浏览器度量逐一抽查按钮/卡片/删除图标）。
- [ ] 每个输入项点击 label 可聚焦对应控件；提交失败自动滚动并聚焦第一个错误字段，错误为「图标 + 文字」。
- [ ] 随机抽测正文、标签、占位符、状态徽章对比度 ≥4.5:1。
- [ ] iPhone（刘海屏）底部内容与按钮不被手势条遮挡；软键盘弹出后当前输入框可见。
- [ ] 在微信内置浏览器完整走通：打开首页 → 提交基本反馈（含 1 张截图）→ 成功页复制编号（或长按复制降级）→ 按编号查询进入详情页。
