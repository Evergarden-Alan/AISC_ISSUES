# 01 · v0.1.2 计划（合并版：范围/设计/任务）

> 基线关系：用户 2026-09-22 明示三项改版指令，构成基线演进（同 v0.1.1 R4 先例）：
> ① 移除管理页（开发者直接克隆 issues 仓库改 md），首页直接列出全部反馈及状态（不再做隐藏过滤）；
> ② 仓库布局改为「反馈 + 附件同目录」，目录名 = 日期+概述+提出者；仓库根目录维护索引 md（反馈/需求两表：序号/关键字/时间/当前进度；时间列 2026-09-22 追加）；表单「提出者」「概述」必填；
> ③ 提交前拦截：无截图/日志 + 复现三字段全空 + 描述过短 → 提示难以定位问题，确认后才能继续。

## 1. 仓库布局（数据面演进）

```
aisc-issues-feedback/
├─ 索引.md                        ← 仓库根：两张表（反馈/需求）
└─ issues/
   ├─ 20260922-导出报表闪退-阿明/
   │  ├─ 反馈.md                  ← 功能路径为 需求.md
   │  ├─ s1-截图.png              ← 附件与 md 同目录
   │  └─ a1-调试日志.log
   └─ issues/_pending/            ← 上传暂存（原 feedback/assets/_pending 迁移）
```

- 目录名：`{YYYYMMDD}-{概述≤20字}-{提出者≤12字}`，非法字符清洗为 `-`；冲突追加 `-2`/`-3`。
- 索引.md 由服务端在**每次新提交时全量重建**（读全部 md 的 status → 中文进度），开发者直接改 md 后最迟下一次提交时同步；每日 cron 顺带重建一次兜底。
- 序号按 created_at 升序派生（删除条目后序号前移，属预期）。

## 2. 站点行为变更

| 项 | v0.1.1 | v0.1.2 |
|---|---|---|
| 管理页 /admin + /api/admin/* | 有 | **删除**（含 ADMIN_TOKEN 环境变量；开发者直接改仓库） |
| 首页 | 回信区双 Tab（仅已回复）| **全部反馈列表**（含状态徽章/筛选/搜索/日期，原 /issues 并入），隐藏过滤移除 |
| 隐藏 status | 全站过滤 | 仅作普通状态展示，**不再过滤任何内容** |
| 详情页路径 | /issue/{id}（id=日期-随机）| /issue/{目录名}（中文目录名）|
| 表单 | nickname 选填 | **nickname 必填**（title 本就必填）|
| 提交拦截 | 无 | 稀薄提交警告（③）|

## 3. 提交拦截（③）

条件（全部满足才拦截）：无截图 ∧ 无日志 ∧（复现步骤/期望结果/实际结果均空）∧ 描述 <15 字。
交互：首次点提交弹出内嵌警示条「未上传截图或日志、未填复现信息且描述较短，可能难以定位问题、降低修复效率」，按钮「我再补充一下」/「仍然提交」；仍然提交则正常走提交流程，不再二次拦截。

## 4. 环境变量变更

- 移除：`ADMIN_TOKEN`（管理页已删）。
- 不变：`GITHUB_PAT`/`REPO_OWNER`/`REPO_NAME`/`FEEDBACK_TOKEN_SECRET`/`NEXT_PUBLIC_SITE_URL`/`CRON_SECRET`/`TURNSTILE_*`/`UPSTASH_*`。
